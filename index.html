LLM Router — Intelligent Cost-Optimization Gateway GitHub ↗
Python · FastAPI · scikit-learn · spaCy · MongoDB · Docker · Kubernetes · OpenAI API
  • Built an intelligent API gateway that scores each incoming LLM query for difficulty and routes it to the cheapest model tier capable of answering correctly — instead of always calling the most expensive model — cutting unnecessary LLM spend without sacrificing answer quality.
  • Trained a logistic regression difficulty classifier (scikit-learn, StandardScaler-normalized) on ~21,500 labeled queries across 4 public benchmarks (ARC-Easy, ARC-Challenge, GSM8K, SQuAD), engineering 7 hand-crafted linguistic features — reasoning-keyword density, rare-word ratio via word-frequency lookup, spaCy-based named-entity count, sub-question count, and average word length — chosen to run in well under 50ms with zero LLM calls.
  • Diagnosed a dataset-shortcut bug where an early version of the classifier scored 96% test accuracy yet failed on realistic, out-of-distribution queries — traced it to the model exploiting a spurious genre artifact (named-entity density) rather than learning true difficulty — and fixed it by blending multiple genres into both classes, landing on a more honest and generalizable 87% held-out accuracy.
  • Designed a FastAPI backend implementing the full routing pipeline behind two endpoints, POST /route and GET /dashboard: difficulty scoring, threshold-based model selection, an OpenAI Responses API call to the selected tier, and asynchronous cost/latency logging to MongoDB via background tasks — adding zero latency to the client-facing response.
  • Logged every routing decision to MongoDB with a privacy-conscious schema — storing only a SHA-256 hash of the query text alongside difficulty score, model used, estimated cost, a computed baseline cost (what the same query would have cost on the strong tier), latency, and token counts — enabling cost-savings analysis without retaining raw user queries.
  • Built a live analytics dashboard and an interactive query-routing demo UI: the dashboard computes total cost savings against a naive always-strongest-model baseline, routing distribution between tiers, and p50/p95/p99 latency percentiles per model directly from MongoDB on each load; the demo UI lets a visitor submit a query and watch the routing decision render in real time.
  • Containerized the stack with Docker Compose and deployed to Kubernetes (Minikube), separating non-secret configuration (model names, threshold) into a ConfigMap from the API key in a Secret; configured a Horizontal Pod Autoscaler scaling the router 1→3 replicas on CPU utilization, and authored manifests portable to AWS EKS/GCP GKE without modification; iteratively designed, built, and debugged the full system end to end using Claude Code.
  • Achieved 87% held-out classifier accuracy; live testing routed 62% of queries to the cheap tier, cutting total cost ~7% versus an always-use-strongest-model baseline.
